ЗАДАНИЕ 3. Декодер Хемминга (8,4) изменённый - графическая схема
=================================================================

ФАЙЛЫ В ПАПКЕ (три уровня иерархии - всё вместе):
   decoder.bdf          - лист декодера: 8 XOR для синдромов, 7 XOR для KP, OR2-цепочка
                           для (P1+P2+P3), блок дешифратора 3-в-8 (U1), 4 XOR исправления,
                           NOT и два AND2 для индикаторов
   decoder_3-8_en.bdf   - дешифратор 3-в-8 с разрешением как отдельный лист:
                           3 NOT + восемь четырёхвходовых AND, 11 элементов
   decoder_3-8_en.bsf   - его символ; в листе декодера стоит блоком U1
   decoder.bsf          - символ декодера: шина IN[7..0] слева, OUT_DATA[3..0] справа
   IN[7..0]             - принятое слово: позиция 1 -> IN7 ... позиция 8 -> IN0
   OUT_DATA[3..0]       - исправленные данные (OUT_DATA0 = D0 ... OUT_DATA3 = D3)
   ONE_ERR, DBL_ERR     - индикаторы одиночной и двойной ошибки
   dec38_truth.json     - таблица истинности ПОДЛИННОГО примитива dec38 из
                           libraries/others/maxplus2, снятая моделированием на уровне
                           ворот: SENSE=1, INHB=0 -> активный уровень 1, индекс = S2 S1 S0;
                           INHB=1 запрещает выход. Наш блок повторяет это поведение.

ЛОГИКА (формулы взяты из плана дословно):
   P1 = K1^D0^D1^D3    P2 = K2^D0^D2^D3    P3 = K3^D1^D2^D3
   KP = K1^K2^D0^K3^D1^D2^D3^K
   ONE_ERR = KP & (P1|P2|P3)        DBL_ERR = !KP & (P1|P2|P3)
   Число SYN = P3 P2 P1 есть номер неисправной позиции (вес P1 = 1, P2 = 2, P3 = 4),
   поэтому дешифратор 3-в-8 - аппаратный аналог таблицы исправления. Исправляются
   ТОЛЬКО позиции 3, 5, 6, 7 (D0, D1, D2, D3): выходы Q1, Q2, Q4, Q8 ни с одним XOR
   исправления не соединены, поэтому ошибка в проверочном бите данные не меняет.

ЧТО ДЕЛАТЬ: quartus_map decoder; quartus_map decoder --generate_functional_sim_netlist;
   quartus_sim decoder; quartus_fit decoder; quartus_tan decoder.

РЕСУРСЫ И ВРЕМЕНА (гостевая Quartus II 5.0):
   устройство: EP1S10F484C5 (семейство Stratix)
   логических элементов: 10 / 10,570 ( < 1 % )
   выводов: 14 / 336 ( 4 % )
   худший tpd: 9.900 ns  (IN[1] -> OUT_DATA[2])
   quartus_map / quartus_fit / quartus_asm / quartus_tan - коды возврата 0, ошибок нет

КОНТРОЛЬ: функциональная симуляция - 24 строк, проверено 6 сигналов,
   расхождений 0 -> PASS.
   Строки воздействия: 16 правильных кодовых слов + 8 сценариев плана (D = 1101).

ПРИМЕЧАНИЕ О НАЗВАНИИ БЛОКА: в плане блок назван дешифратор 3-в-8. В Quartus II 5.0
   есть подлинный примитив dec38 (libraries/others/maxplus2) с портами SENSE, INHB,
   S2, S1, S0 -> Y0..Y7; его таблица снята и приложена. Текст-генератор не может
   полагаться на разрешение этого примитива по имени в гостевой установке, поэтому
   дешифратор построен отдельным листом из ворот с той же функцией.
