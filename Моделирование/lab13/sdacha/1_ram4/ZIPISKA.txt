ФУНКЦИЯ. ОЗУ 4 слова по 1 биту. При WE=1 фронт CLK пишет D в ячейку, выбранную
адресом A1A0; при WE=0 на Q - содержимое выбранной ячейки, причём невыбранные
ячейки отключены тристадами, поэтому шина остаётся в Z. Именно Z, а не 0, и
есть
признак исправного трёхстадного ОЗУ: X на шине означал бы конфликт водителей,
а 0 - что невыбранные ячейки подтянуты к земле, то есть шины как таковой нет.

ЛОГИКА И ПРИНЦИП РАБОТЫ (по ram4.json, проверено по ram4.bdf).
четыре триггера DV (DFFE), дешифратор 2-в-4 на элементах И-НЕ, четыре
   вентиля строба записи и четыре трёхстальных буфера на общую шину Q.
   Декодирование, как оно вышло из листа (раздел decode в report_data.json):
      addr_0    = !A0*!A1
      addr_1    = A0*!A1
      addr_2    = !A0*A1
      addr_3    = A0*A1
      en        = EN_i = addr_i * WE
      oe        = OE_i = addr_i * !WE
То есть выбор ячейки даёт адрес и WE вместе (EN_i = addr_i * WE), а
   разрешение
   на чтение выставлено только при WE=0 (OE_i = addr_i * !WE): записываемая
   ячейка не может одновременно вести шину, конфликта не возникает ни в одной
   фазе. Асинхронные входы ячеек PRN и CLRN подняты на VCC, поэтому постоянно
   выключены и ячейка живёт исключительно тактом.
   Примитив GND в листе остался неиспользованным, о чём говорит единственное
предупреждение синтеза (Analysis & Synthesis was successful. 0 errors, 1
   warning):
      Warning: Primitive "GND" of instance "G0" not used

СМЫСЛ ИЗМЕРЕННЫХ ЗАДЕРЖЕК. tpd 9.366 ns (A0 -> Q) - это
путь выбора ячейки до шины, он и есть время обращения; tco 7.804 ns (F0 -> Q)
- с момента такта до появления
данных на Q; tsu 3.491 ns и th -1.868 ns - окно вокруг такта, в которое
должны успеть адрес и данные. Провалов нет (0 путей), значит схема на
EP1S10F484C5 работает быстрее, чем предписано ограничениями.

ЧТО ДЕЛАТЬ В QUARTUS II 5.0:
  1. File -> Open Project -> <имя>.qpf   (НЕ .bdf открывать!)
2. Processing -> Start Analysis & Synthesis               - проверить, что
  схема читается
  3. Processing -> Generate Functional Simulation Netlist
4. Tools -> Run Simulation Tool -> Functional Simulation  - получить волны
  (*.sim.vwf)
5. Processing -> Start Timing Analysis                    - получить
  задержку (*.tan.rpt)
Все файлы уже в папке; расформировывать её нельзя: Quartus ищет детские .bdf,
символы
.bsf и источники VHDL/AHDL только в каталоге проекта, а .qsf перечисляет их по
basename.
