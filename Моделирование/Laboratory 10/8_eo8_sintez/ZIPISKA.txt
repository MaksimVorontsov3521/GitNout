ЗАДАНИЕ 8. Синтезируемость схемы eo8
=====================================

ПРОЕКТ: тот же, что 3b_eo8_vhd (eo8.vhd + eo8.qpf), но задача здесь другая -
доказать, что код из задания 5 превращается в железо, а не только моделируется.

ЧТО СМОТРЕТЬ В QUARTUS:
   1. Tools -> RTL Viewer              - дерево XOR, 9 входов, 2 выхода
   2. Assignments -> Device -> Stratix, DEVICE AUTO (фиттер выбрал EP1S10F484C5)
   3. Processing -> Start Fitter       -> Technology Map Viewer
   4. Отчёт: Analysis & Synthesis, Fitter, Assembler, Timing Analyzer - все 0 ошибок

ТАБЛИЦА РЕСУРСОВ (факт из eo8.fit.rpt):
   Total logic elements .............. 3 / 10,570  ( < 1 % )
       -- Combinational, no register . 3
       -- Register only .............. 0
       -- Combinational + register ... 0
   Total pins ........................ 11 / 336    ( 3 % )
   Total memory bits ................. 0 / 920,448 ( 0 % )
   Total PLLs / DLLs ................. 0 / 0

ОЖИДАНИЕ ИЗ ПЛАНА -> ФАКТ:
   ~4 LE  ->  3 LE   (свёртка 9 входов деревом XOR упаковалась плотнее оценки:
                      Quartus свёл два первых разряда в одну таблицу поиска)
   0 регистров -> 0  (все три LE комбинационные)
   11 пинов -> 11    (9 входов + EVEN + ODD) - совпало ровно
   0 бит памяти -> 0

ПРИЗНАКИ ПЛОХОГО КОДА, КОТОРЫХ НЕТ: ни одного сообщения о защёлках (latch),
о неполных назначениях (incomplete assignment), о выводе, повисшем без
присваивания. Проверено во всех восьми проектах лаборатории - предупреждений
нет ни в одном .map.rpt.

ВЫВОД: код синтезируем, чисто комбинационный, минимальный по ресурсам.
Лежащие рядом отчёты (eo8.fit.rpt, eo8.map.rpt, eo8.flow.rpt, eo8.tan.rpt,
eo8.pin, eo8.map.eqn) - доказательства без доступа к GUI.
