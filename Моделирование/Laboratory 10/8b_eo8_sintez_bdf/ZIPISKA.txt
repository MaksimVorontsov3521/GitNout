ЗАДАНИЕ 8 (вариант на схеме). Синтезируемость графического eo8
==============================================================

ПРОЕКТ: eo8.bdf из задания 3a - тот же контролёр, что и 3b, но описанный
четырьмя блоками parity2, а не циклом в тексте.

ЗАДАЧА ПУНКТА: показать, что в железо превращается ОБЕ реализации, а не только
текстовая. Смотреть:
   1. Tools -> RTL Viewer              - дерево XOR, 9 входов, 2 выхода
   2. Assignments -> Device            - Stratix, DEVICE AUTO
   3. Processing -> Start Fitter       -> Technology Map Viewer
   4. Отчёты: Analysis & Synthesis, Fitter, Assembler, Timing Analyzer

ТАБЛИЦА РЕСУРСОВ (факт из eo8.fit.rpt, полученный перекомпиляцией этой папки):
   Total logic elements .............. 3 / 10,570  ( < 1 % )
       -- Combinational, no register . 3
       -- Register only .............. 0
       -- Combinational + register ... 0
   Total pins ........................ 11 / 336    ( 3 % )
   Total memory bits ................. 0 / 920,448 ( 0 % )

СРАВНЕНИЕ С 8a (VHDL) - главный вопрос задания:
   8a: 3 LE (все комбинационные), 11 пинов, 0 регистров, 0 бит памяти
   8b: 3 LE (все комбинационные), 11 пинов, 0 регистров, 0 бит памяти
   Итог ОДИН И ТОТ ЖЕ. Синтезатор не различает способ описания: свёртка
   9 входов деревом XOR и пирамида из четырёх ячеек дают одинаковую сеть.

ОЖИДАНИЕ ИЗ ПЛАНА -> ФАКТ:
   ~4 LE -> 3 LE;  0 регистров -> 0;  11 пинов -> 11 (ровно);  0 памяти -> 0.

ПРЕДУПРЕЖДЕНИЙ НЕТ: ни сообщений о защёлках (latch), ни неполных назначений,
ни висящих выходов, кроме трёх En в пирамиде - они оставлены неподключёнными
намеренно (для выходов это допустимо), и Quartus принимает проект с 0 ошибок
и 0 предупреждений.

ПОРЯДОК КОМАНД В КОМАНДНОЙ СТРОКЕ (важно, на этом споткнулась сборка):
   quartus_map eo8                          - обычный запуск, готовит базу
   quartus_fit / quartus_asm / quartus_tan  - после обычного map
   quartus_map eo8 --generate_functional_sim_netlist  - только потом
   quartus_sim eo8
Если вызвать map СРАЗУ с флагом --generate_functional_sim_netlist, то
Analysis & Synthesis проходит (0 ошибок), но фиттер отвечает
   Error: Run Analysis and Synthesis (quartus_map) with top-level entity name
          "eo8" before running Fitter (quartus_fit)
и asm/tan падают следом (коды 3). Флаг перестраивает базу под функциональный
нетлист и не оставляет данных для размещения. В GUI этой проблемы нет.
