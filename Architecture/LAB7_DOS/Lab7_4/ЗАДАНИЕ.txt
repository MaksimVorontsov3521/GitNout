Задание — Lab7_4 (шаг 4 из A7.txt, строки 33–36)

ФОРМУЛИРОВКА:
  "4. Напишите программу, выполняющую команды FPU,
    вызывающую и реагирующую на особый случай FPU (обработчик
    прерывания сообщает о  наступлении особого случая по результату
    анализа регистра состояния)."

ЯЗЫК / СРЕДСТВО: чистый ассемблер (TASM 4.1), .286 + .MODEL TINY -> .COM
ИСХОДНИК:  lab7_4.asm

ЧТО ДЕЛАЕТ ПРОГРАММА (по пунктам задания):
  1) запомнить старый вектор 75h (int 21h/35h) и 16h, установить свои
     обработчики (int 21h/25h) - как требует механизм A7.txt, строки 105-110;
  2) FINIT -> FSTCW, снять МАСКУ одного из особых случаев (бит 0..5 в 0)
     и загрузить слово управления обратно (FLDCW);
  3) ВЫЗВАТЬ особый случай командой FPU (деление 1.0/0.0 -> Z;
     0.0/0.0 и FSQRT(-1) -> I; 1e300*1e300 -> O; 1e-300*1e-300 -> U;
     1.0/3.0 -> P; денормализованный операнд -> D) и выполнить FWAIT
     (A7.txt, строки 186-200 и 202-212 про WAIT/NO-WAIT и Pentium);
  4) ПРОЧИТАТЬ регистр состояния (FSTSW) и по битам 0..5 определить КЛАСС
     особого случая по приоритету (A7.txt, строки 84-99) - это и есть
     "реакция на особый случай по результату анализа регистра состояния";
  5) передать управление обработчику: int 75h (вектор, который назвал бы
     процессор при NE=0). Обработчик: FSTSW -> разбор класса, FCLEX (сброс),
     возврат маски к 037Fh (FLDCW), чтобы исключить повторный вход,
     EOI контроллеру прерываний (out 20h,20h) - обязательно для IRQ13,
     счётчик входов, IRET. Обработчик НЕ печатает: пишет класс и слова в
     глобальные переменные, печать делает основной код;
  6) основной код печатает: CW до/после, SW с разбором, класс особого случая,
     ответ FPU по умолчанию (A7.txt, строки 84-99: бесконечность, QNaN,
     денормал, +-Inf/Nmax, 0, округленный результат) - побайтно из FSAVE;
  7) отдельно: CR0 и бит NE машинным кодом (db 0Fh,20h,0C0h / db 66h,0A3h),
     чтобы показать, почему в DOSBox нельзя определить NE;
  8) восстановить старые вектора (int 21h/25h) и маску перед выходом.

ОСОБЕННОСТИ:
  ДОКАЗАНО ЗОНДОМ (Zond_Lab7.txt, P5): DOSBox 0.74-3 НЕ доставляет
  немаскированные исключения x87 наружу - при CW=037B и 1.0/0.0 флаг ZE
  в слове состояния выставлен (SW=3904), но обработчики на 75h и 16h не
  вызываются (счётчик 0) и ES=0. Поэтому особый случай реально возникает
  (видно по регистру состояния), а вызов обработчика выполняется программной
  командой int 75h - тот же вектор, что аппаратный при NE=0. Программа
  печатает это разделение явно, чтобы не выдавать эмулятор за реальное ЖД.
  Вектор 75h до установки в DOSBox = 0000:0000 (зачем-то свободен).
  Обработчик обязан послать EOI (out 20h,20h), иначе следующая аппаратная
  IRQ13 не придёт; возврат маски нужен, чтобы int 75h не зациклился.
  .386 не используется (ломает tlink /v /t), данные после кода.
