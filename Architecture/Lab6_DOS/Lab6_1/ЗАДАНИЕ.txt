Задание — Lab6_1 (шаг 1 из A6.txt, строки 42–46)

ФОРМУЛИРОВКА:
  "1. Реализуйте выполнение вашей ПП через программное прерывание
   (команда int) для чего: запомните старый вектор прерывания,
   установите новый, введите параметры ПП, выполните прогр.
   прерывание, обработайте данные в ПП (в программе обработке
   прерывания), выйдите в основную программу, выведите результат."

ЯЗЫК / СРЕДСТВО: C + встроенный ассемблер, компилятор TCC (Turbo C 2.01),
модель памяти small (-ms), формат EXE.

ИСХОДНИК:  Lab6.c

ЧТО ДЕЛАЕТ ПРОГРАММА (по пунктам задания):
  1) old_f0 = getvect(0xF0)                 — запомнить старый вектор
  2) disable(); setvect(0xF0, isr_f0); enable() — установить новый
     (вектор 0xF0 — пользовательский, разрешённый: не занят DOS/BIOS/ЦП)
  3) ввести параметры ПП ДВУМЯ способами:
       (a) общая область памяти — глобальные переменные memA, memB;
       (b) регистры — AX=regIn1, BX=regIn2 (загружаются в asm блоке)
  4) geninterrupt(0xF0)  и  asm int 0F0h    — выполнить программное прерывание
  5) обработать данные ВНУТРИ ПП: сумма, произведение, сумма по массиву
  6) выход в основную программу — IRET (генерирует компилятор)
  7) вывести результат — printf уже в main
  8) setvect(0xF0, old_f0)                  — восстановить старый вектор

ОСОБЕННОСТИ:
  - Обработчик НЕ печатает (printf/int 21h из ПП небезопасны): он только
    пишет результаты в глобальные переменные, вывод делает main.
  - Порядок параметров void interrupt в Borland: (bp, di, si, ds, es,
    dx, cx, bx, ax) — по нему обработчик читает свои регистры из кадра.
  - IVT контролируется напрямую, чтением слова по абсолютному адресу: rdw(0, 0xF0*4)
    и rdw(0, 0xF0*4+2). Это собственный helper на inline asm, а НЕ peek(): в ANSI-режиме
    TCC макросы peek/poke/MK_FP скрыты в DOS.H под #if !__STDC__ и недоступны.
