## 4. Ключевые технические решения (обоснование)

**Кадр обработчика `void interrupt` в Borland/Turbo C** — пролог сохраняет 9 слов, поэтому:

```
[bp+0]=BP  [bp+2]=DI  [bp+4]=SI  [bp+6]=DS  [bp+8]=ES
[bp+10]=DX [bp+12]=CX [bp+14]=BX [bp+16]=AX   ← пролог компилятора
[bp+18]=IP [bp+20]=CS [bp+22]=FLAGS           ← кладёт ПРОЦЕССОР
```

Отсюда `add [bp+18], 2` из строки 53: 18 = 9×2 байт пролога, а 2 = длина `DIV BX` (`F7 F3`). Этот вывод воспроизводится **вручную** в `Lab6_5` (чистый ASM): пролог `push ax,bx,cx,dx,es,ds,si,di,bp` + `mov bp,sp` даёт ровно тот же кадр.

Подтверждение порядка параметров взято из штатного примера поставки: `C\TCC\SAMPLES\tc_tsr10\PRT2DISK.C:66` — `void interrupt intr_0x17(unsigned bp, di, si, ds, es, dx, cx, bx, ax)`.

**Выбор векторов:**

- шаг 1 — `0F0h` (пользовательский, разрешённый;пример из задания: `getvect(0xF0)`);
- шаги 3–4 — `00h` (Divide Error), входит в первые десять (00h…09h), как требует строка 49–50.

**Демонстрируемые способы передачи параметров ПП** (оба, чтобы покрытие было полным): общая область памяти (глобальные переменные C, доступ по `offset` из asm) и регистры (AX/BX/CX/SI, читаемые обработчиком из собственного кадра).

**Обработчик не печатает.** `printf`/`int 21h` из ПП небезопасно (DOS не реентерабелен), поэтому ПП только пишет данные в глобальные переменные и в слоты кадра; вывод выполняет `main`.

## 6. Как запускать (проверка)

Открыть в VS Code **конкретную папку** (например `…\Lab6_DOS\Lab6_1`) и нажать **Ctrl+Shift+B** — как в Lab5. Очередь проверки:

1. `Lab6_1` → ожидается `SUM=123Bh` (0x1234+0x0007), `PROD=…`, `reg SUM=C1h` (0x00A5+0x001C), записи в IVT до/после/восстановлена, `hits=2`.
2. `Lab6_2` → стек вырос на **6 байт = 3 слова**; `SP после IRET = SP до INT`; внутри ПП `TF=0`, `IF=0`; `CALL NEAR → 1`, `CALL FAR → 2`.
3. `Lab6_3` → входы в ПП = 1, делитель исправлен на 1, DIV исполняется повторно: итог `24680 / 1 = 24680`, остаток `0`.
4. `Lab6_4` → дамп 12 слов кадра (дельта SP = 24 байта), `IP после add = IP до add + 2`, `entries = 1`, результат `3525` ост. `5` выдан через слоты `[bp+16]`/`[bp+10]`.
5. `Lab6_5` → те же числа, что и `Lab6_4` (`3525`, ост. `5`), но на чистом ассемблере; дельта SP там 6 байт = 3 слова, потому что пролог пишется вручную и снимается SP до него.

**Риск закрыт (§8).** Ранее считалось, что автономно проверить нельзя: DOSBox — GUI-процесс, а `-log`/`-nogui` не дают вывода программы. Причины были две: (1) PowerShell не ждал завершения GUI-процесса, поэтому файлы читались до того, как они создавались; (2) ключ `-exit` привязан к позиционному аргументу-имени программы и в цепочке `-c …` эмулятор не закрывает. Решение — §8: внутренняя команда DOSBox `-c "exit"`, явное `WaitForExit()` и редирект вывода ВНУТРИ DOS. Прогон всех пяти выполнен, вывод зафиксирован в `Run_Result.md`.

Отладка по кадру: задача `Compile and Debug in TD (DOSBox)` → `td` показывает `SS:SP` на входе в ПП и `dump` стека, чем подтверждается таблица из §4.

## 8. Как смотреть результат программы автономно (без человека у клавиатуры)

Реализовано в `autotest.ps1`; вызывается из VS Code третьей задачей или напрямую:

```
powershell -NoProfile -ExecutionPolicy Bypass -File autotest.ps1            # все пять
powershell -NoProfile -ExecutionPolicy Bypass -File autotest.ps1 -Only Lab6_3
```

Три условия, без которых перехват не работает (каждое проверено опытным прогоном):

1. **DOSBox — GUI-процесс.** `& dosbox.exe …` и `Start-Process` без ожидания возвращают
   управление мгновенно, поэтому чтение `build\run.txt` давало «файл не найден»: эмулятор
   ещё работал. Нужно `Start-Process -PassThru` и явное `$p.WaitForExit()`.
2. **Закрытие по внутренней команде.** Ключ `-exit` действует только вместе с позиционным
   аргументом (именем программы). В цепочке `-c …` эмулятор закрывает только `-c "exit"`;
   без него DOSBox висит с окном, а `WaitForExit` уходит в таймаут.
3. **Вывод берётся из редиректа внутри DOS**, а не из консоли Windows:
   `lab6 > d:\build\run.txt`, диагностика транслятора → `d:\build\cc.txt`.
   Перехватить stdio GUI-процесса нельзя, а `-log` пишет журнал эмулятора, не вывод программы.

Плюс ожидание клавиши должно быть отключено: в исходниках оно спрятано под `NOWAIT`
(`#ifndef NOWAIT … getch(); … #endif` в C, `IFNDEF NOWAIT … int 16h … ENDIF` в ASM),
а скрипт передаёт `-DNOWAIT` (TCC) и `/dNOWAIT` (TASM). Интерактивный `Compile and Run`
этот символ не использует, поэтому `Ctrl+Shift+B` по-прежнему ждёт нажатия клавиши.

Замечание по кодировке: `autotest.ps1` сохранён в UTF-8 **с BOM** — Windows PowerShell 5.1
читает файл без BOM как CP1251, и кириллица в комментариях ломает разбор синтаксиса.

Итог прогона: `Run_Result.md` — фактические выводы всех пяти шагов, ошибок сборки нет.
