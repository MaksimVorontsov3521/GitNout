## 1. Программное прерывание как средство вызова ПП: достоинства и недостатки

**Механизм.** Команда `int n` возбуждает программное прерывание: процессор кладёт в стек
FLAGS, CS, IP и переходит по вектору `IVT[n]` — то есть управление передаётся не по адресу,
записанному в команде, а по адресу, прочитанному из таблицы векторов. Команда `iret`
возвращает управление: извлекает те же 3 слова (IP, CS, FLAGS).

**Достоинства**

1. **Косвенный переход = заменяемость.** Вектор можно переопределить в рантайме
   (`setvect`), подменив ПП без пересборки вызывающего кода. Так строятся TSR-резиденты
   и драйверы: `Lab6_1` и `Lab6_5` меняют вектор, работают, затем возвращают старый.
2. **Единая точка входа для приложения и системы.** Один и тот же `int 21h` обслуживает
   тысячи разных программ — DOS-вызовы существуют именно благодаря этому механизму.
3. **Автоматическое сохранение флагов.** В отличие от `call`, прерывание сохраняет FLAGS,
   поэтому обработчик может менять условия (и `ZF`/`CF`) без риска для вызывающего кода.
4. **Автоматический запрет вложенности.** Процессор сбрасывает `IF` и `TF` на входе,
   поэтому обработчик защищён от рекурсии по маске (в `Lab6_2` видно `TF=0, IF=0` внутри ПП).
5. **Параметры в регистрах + память** — оба способа демонстрируют `Lab6_1`/`Lab6_3`.

**Недостатки**

1. **Дороже вызова.** 3 слова в стек вместо 1 (`CALL NEAR`), плюс чтение вектора из IVT,
   плюс полный пролог/эпилог регистров — в `Lab6_2` дельта стека: INT → 3 слова,
   CALL NEAR → 1, CALL FAR → 2.
2. **Нет контроля прототипа.** Параметры передаются «по соглашению»: компилятор не
   проверяет типы и количество, ошибка проявится только в рантайме.
3. **Обработчик не может печатать.** `printf`/`int 21h` из ПП небезопасны (DOS не
   реентерабелен), поэтому во всех программах ПП только пишет данные в память/кадр,
   а вывод делает `main`.
4. **Опасность испортить чужой вектор.** Забыть `setvect` обратно — оставить систему с
   висельным обработчиком; отсюда обязательный шаг 4 в `Lab6_1`/`Lab6_5`.
5. **Скрытость управления.** Переход не виден в листинге вызывающего кода: отладка только
   через `TD` (задача «Compile and Debug in TD (DOSBox)»).

## 2. Вектор прерывания. Разрешённые и запрещённые вектора

**Вектор** — 32-битная (4-байтная) ячейка: младшее слово = `IP`, старшее = `CS`.
256 векторов × 4 байта = 1 КБ: абсолютные адреса `00000h…003FFh` (`0000:0000…0000:03FF`).
Адрес вектора = `тип прерывания × 4` (пункт 4 описания INT, строки 74–75).

| Диапазон | Назначение | Приложение |
|---|---|---|
| 00h–07h | исключения процессора (00h деление на нуль, 01h TRAP, 02h NMI, 03h breakpoint, 04h INTO, 05h BOUND, 06h invalid opcode, 07h device not available) | запрещён (только чтение/кратковременный перехват) |
| 08h–0Fh | аппаратные IRQ контроллера 8259 | зарезервирован |
| 10h–1Ah | службы BIOS | зарезервирован |
| 20h–3Fh | службы DOS | зарезервирован |
| 40h–6Fh | таблицы и локальные данные DOS/BIOS | зарезервирован |
| 70h–77h | IRQ второго 8259 | зарезервирован |
| 78h–B7h | локальные / пользовательские | допустим с осторожностью |
| B8h–FFh | пользовательские | **разрешён** |

Для шага 1 выбран **0F0h** — пользовательский, свободный (тот же выбор в примере задания,
строки 99–104). Для шагов 3–4 — **00h**, один из первых десяти (строки 49–50).

## 3. Какие регистры запоминаются в стеке

**Автоматически, при входе в ПП (пункты 1, 3, 6 описания INT, строки 69–78):**

| Порядок укладки | Содержимое | Смещение от вершины стека |
|---|---|---|
| 1-м | FLAGS | `[SP+4]` |
| 2-м | CS | `[SP+2]` |
| 3-м | IP (адрес возврата) | `[SP]` — вершина |

То есть на макушке стека — IP, затем CS, затем FLAGS (строки 79–80). Одновременно
процессор обнуляет `TF` и `IF` (строки 71–73), а их прежние значения остаются в кадре.

**Программно, прологом компилятора.** Borland/Turbo C для `void interrupt` сохраняет
9 слов, поэтому кадр целиком:

```
[bp+0 ]=BP   [bp+2 ]=DI   [bp+4 ]=SI   [bp+6 ]=DS   [bp+8 ]=ES
[bp+10]=DX   [bp+12]=CX   [bp+14]=BX   [bp+16]=AX      <- пролог (9 слов = 18 байт)
[bp+18]=IP   [bp+20]=CS   [bp+22]=FLAGS                <- процессор (3 слова)
```

**Отсюда `add [bp+18], 2` из строки 53:** 18 = 9 слов пролога × 2 байта, а 2 = длина
`DIV BX` (`F7 F3`). `Lab6_5` воспроизводит этот пролог вручную (`push ax,bx,cx,dx,es,ds,
si,di,bp` + `mov bp,sp`), показывая, что 18 — не свойство прерывания, а свойство пролога.

`IRET` извлекает ровно 3 слова: IP, CS, FLAGS (строки 88–93). Регистры `AX…BP`
восстанавливаются эпилогом, а не `IRET`.

## 4. Отличие от аппаратного прерывания

| Признак | Программное прерывание (`int n`) | Аппаратное (IRQ через 8259) |
|---|---|---|
| Источник | исполнительная команда внутри программы | сигнал внешнего устройства на шине |
| Момент возникновения | детерминирован (в точке команды) | асинхронен, между командами |
| Маскирование | не действует: `IF=0` не мешает выполнить `int n` | действует: `CLI` блокирует маскируемые IRQ (NMI — нет) |
| Тип прерывания | содержится в байте команды | поступает из контроллера прерываний во время INTA |
| Разрешение/запрет | «разрешение/запрет прерывания в регистре флагов и во внешнем устройстве» (строки 34–35) — нужно и там, и там | то же |
| Стековой кадр | одинаковый: FLAGS, CS, IP | одинаковый: FLAGS, CS, IP |
| Используемые регистры | обработчик сам сохраняет всё нужное (строки 36–37) | то же |
| Вложенность | программируется программистом (строка 38) | программируется масками 8259 + `IF` |

Суть отличия: **способ получения номера вектора**. При `int n` номер зашит в команду,
при аппаратном — приходит от контроллера; остальной механизм (стек, сброс TF/IF, `IRET`)
идентичен.

## 5. Отличия особых случаев от других источников прерываний

1. **Источник — сам процессор**, а не команда и не внешнее устройство: внутренняя ошибка
   при исполнении команды (деление на нуль, `INTO` при `OF=1`, выход за границы массива
   `BOUND`, недопустимая команда, отказ сопроцессора).
2. **Непредсказуемая точка возникновения.** Особый случай возбуждается *при исполнении*
   команды, поэтому адрес возврата указывает на **ту же** команду, а не на следующую.
3. **Повторное исполнение по умолчанию.** После `IRET` процессор исполняет ту же команду
   снова. Отсюда два разных приёма в работе:
   - `Lab6_3`: обработчик исправляет данные в кадре (`[bp+14] = 1)), `IP` **не** трогает →
     `DIV` повторяется и завершается успешно;
   - `Lab6_4`/`Lab6_5`: обработчик **пропускает** команду — `add [bp+18], 2` → `DIV`
     исполняется 0 раз, результат выдаётся через слоты `[bp+16]` (AX) и `[bp+10]` (DX).
4. **Вектор фиксирован и занят системой** (00h–07h), приложение не выбирает номер само.
5. **Заполнение стека то же самое** — FLAGS, CS, IP (это и есть ответ на «ЧТО НУЖНО
   СДЕЛАТЬ», пункты 2 и 4): исключение и программное прерывание неразличимы по кадру,
   различаются только источником события.

## 6. Источники особых случаев

| Вектор | Особый случай | Источник |
|---|---|---|
| 00h | Divide Error | `DIV`/`IDIV` с нулевым делителем или с частным, не помещающимся в разряд — **используется в работе** |
| 01h | TRAP | флаг `TF=1` (пошаговый режим отладчика, `TD`) |
| 02h | NMI | немаскируемый вход контроллера (сбой памяти, кнопка Reset) |
| 03h | Breakpoint | команда `INT 3` (точка останова отладчика) |
| 04h | Overflow | команда `INTO` при `OF=1` |
| 05h | BOUND | `BOUND` — индекс вне границ массива |
| 06h | Invalid Opcode | недопустимая/неизвестная комбинация байтов, `INT n` без обработчика |
| 07h | Device Not Available | отсутствие сопроцессора 8087 при команде 8087 |
| 08h | Double Fault | вторая ошибка при обработке первой |
| 09h | Coprocessor Segment Overrun | сопроцессор сменил сегмент во время вычислений |

Прочие источники прерываний, не входящие в особые случаи: команды `INT n` (программные),
сигналы 8259 (аппаратные), `INT 21h` (службы DOS).

## 7. Сводка заполнения стека по всем программам

Значения **подтверждены автопрогоном в DOSBox** (`autotest.ps1`, фактический вывод —
`Run_Result.md`): все пять программ собраны без ошибок, числа ниже сняты с реального
запуска, а не рассчитаны.

| Программа | Событие | Что кладёт ЦП | Что кладёт пролог | Дельта SP на момент снятия снимка |
|---|---|---|---|---|
| `Lab6_1` | `INT 0F0h` | FLAGS, CS, IP | 9 слов (`AX…BP`) | 2 входа в ПП, вектор восстановлен 0000:0000 |
| `Lab6_2` | `INT 0F0h` | FLAGS, CS, IP | нет (пролог пишется вручную после снимка) | **6 байт = 3 слова** (SP FFFE→FFF8), стек сбалансирован |
| `Lab6_3` | исключение 00h | FLAGS, CS, IP | 9 слов | 1 вход, DIV исполнена дважды: 24680 / 1 = 24680 |
| `Lab6_4` | исключение 00h | FLAGS, CS, IP | 9 слов | **24 байта = 12 слов**, IP 0430h→0432h, 3525 ост. 5 |
| `Lab6_5` | исключение 00h | FLAGS, CS, IP | 9 слов (вручную) | 6 байт до пролога, 24 после; IP 01C1h→01C3h, слоты 0DC5h:0005h |
| — | `CALL NEAR` | — | — | 1 слово (`IP`) — замерено: `words = 1` |
| — | `CALL FAR` | — | — | 2 слова (`CS:IP`), флаги НЕ сохраняются — замерено: `words = 2` |

**Проверка на реальном железе (эмуляторе).** `Lab6_2` снял кадры тремя способами и
получил ровно предсказанное: `INT 0F0h` → 3 слова (IP, CS, FLAGS), `CALL NEAR` → 1 слово,
`CALL FAR` → 2 слова; `FLAGS` внутри ПП 7093h против 7293h до и после — то есть процессор
сбросил `IF` (бит 9) и `TF` (бит 8), а `IRET` их вернул. `Lab6_4` и `Lab6_5` показали
сдвиг адреса возврата на 2 байта (0430h→0432h и 01C1h→01C3h), что и есть `add [bp+18], 2`.

**Главный вывод работы:** прерывание — это *косвенный межсегментный вызов ПП через
фиксированную таблицу векторов*, дополнительно сохраняющий FLAGS; поэтому возврат из него
выполняется `IRET` (3 слова), а не `RET` (1–2 слова). Особый случай отличается только
источником события и тем, что по умолчанию повторяет команду — управляется сдвигом `IP`
в кадре, то есть `add [bp+18], 2`.
